01 · VISÃO GERAL

O que é o DOM Pagamentos?

DOM Pagamentos é uma camada de orquestração sobre o PSP Asaas. O merchant não precisa ter contrato direto com o Asaas – ele apenas chama uma API REST simples e recebe uma URL de pagamento pronta para enviar ao cliente final.

🔗

Payment Link

Gera uma URL de pagamento que aceita Pix, boleto ou cartão. O cliente escolhe o método.

🔔

Webhook

Notificação automática quando o pagamento é confirmado. Garante consistência via retry.

🏦

Asaas como PSP

Toda a liquidação financeira ocorre no Asaas. DOM abstrai a API deles para você.

📡

Callback

Após confirmação, DOM notifica o sistema do merchant com o status atualizado.

Arquitetura em 3 camadas

CamadaResponsabilidadeTecnologia
API REST Recebe requisições do merchant, valida, cria o link no Asaas Spring Boot + OpenAPI
Eventos Processa webhooks do Asaas com retry e dead-letter queue Apache Camel
Callback Notifica o sistema do merchant após confirmação HTTP POST (configurável)
Sem PCI-DSS para o merchant. O cliente final digita os dados do cartão diretamente na página hospedada pelo Asaas. O merchant nunca toca em dados sensíveis.

03 · GUIA DE INTEGRAÇÃO

Passo a Passo

Obtenha suas credenciais

Crie uma conta no painel DOM Pagamentos e copie o API_KEY. Ele será enviado como header X-API-Key em todas as requisições.

Crie um Payment Link

Envie uma requisição POST com o valor e nome do produto.

// Requisição
POST https://api.dompagamentos.com.br/api/v1/payments/link
Content-Type: application/json
X-API-Key: sua_chave_aqui

{
  "name":            "Serviço de Design – Pacote Pro",
  "description":     "5 artes + 2 revisões",
  "amountInCents":   29900,
  "callbackUrl":     "https://meu-sistema.com/webhooks/pagamentos",
  "expiresAt":       "2026-04-14T23:59:00Z"   // opcional
}
Receba a URL de pagamento

A resposta traz a URL pronta para enviar ao cliente e o paymentId para rastrear o pagamento.

// Resposta 201 Created
{
  "paymentId":  "pay_8f2a1b3c4d",
  "url":         "https://asaas.com/c/8f2a1b3c4d",
  "status":      "PENDING",
  "amountInCents": 29900,
  "createdAt":   "2026-03-14T10:00:00Z"
}
Envie a URL ao cliente

Cole o valor de url no WhatsApp, e-mail ou SMS. O cliente acessa a página do Asaas e escolhe Pix, boleto ou cartão — sem necessidade de cadastro.

Configure o endpoint de callback

Quando o pagamento for confirmado, DOM enviará um POST para o callbackUrl que você informou. Implemente esse endpoint no seu sistema.

// Payload que você receberá no callbackUrl
{
  "event":       "PAYMENT_RECEIVED",
  "paymentId":   "pay_8f2a1b3c4d",
  "status":      "RECEIVED",
  "amountInCents": 29900,
  "paidAt":      "2026-03-14T11:35:22Z",
  "paymentMethod": "PIX"          // PIX | BOLETO | CREDIT_CARD
}
Valide a autenticidade do callback. DOM assina cada notificação com o header X-DOM-Signature (HMAC-SHA256 do body + seu API_KEY). Rejeite chamadas sem assinatura válida.

05 · RESILIÊNCIA E RETRIES

Como o Webhook é Processado

O DOM usa Apache Camel para processar notificações do Asaas de forma resiliente. Se o banco de dados ou o callbackUrl do merchant estiver instável, o sistema garante entrega eventual sem perda de eventos.

1

Recebimento

Asaas chama POST /webhooks/asaas. DOM responde 200 imediatamente sem processar.

2

Enfileiramento

O evento é publicado numa fila interna do Camel para processamento assíncrono.

3

Retry automático

Em caso de falha: 3 tentativas com backoff exponencial (5s, 25s, 125s).

4

Dead Letter Queue

Após 3 falhas, o evento vai para a DLQ. O time de operações é alertado para re-processar manualmente.

Retry no callback do merchant

Quando DOM tenta notificar seu callbackUrl e recebe erro HTTP ou timeout, o mesmo mecanismo de retry é aplicado. Para garantir idempotência: 

// O campo "paymentId" é único por evento.
// Se você receber o mesmo paymentId duas vezes, ignore a segunda chamada.

if (await db.payments.exists({ paymentId, status: 'RECEIVED' })) {
  return res.status(200).json({ ok: true, idempotent: true });
}

// senão, processe normalmente
await db.payments.update({ paymentId, status: 'RECEIVED' });
